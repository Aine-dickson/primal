# Interactive Scientific Visualization DSL: Test Case Catalogue

> **Purpose:** A reference catalogue of concepts the system should eventually be able to author, simulate, visualize, animate, and/or interact with.
>
> **Important:** This is deliberately a *case catalogue*, not a proposed DSL specification. We should not remove a case merely because we don't yet know how to represent it. Abstractions and limits should emerge from analyzing these cases.

- A spatial simulation
- A graph
- An equation
- A numerical readout
- A diagram
- A timeline
- A table
- A textual annotation
- A narration track

Example:

```text
Projectile model
       │
       ├── Spatial view
       │      └── projectile trajectory
       │
       ├── Graph view
       │      └── y(t)
       │
       ├── Vector view
       │      └── velocity
       │
       ├── Equation view
       │      └── y(t) = ...
```

# Guiding Principle

The catalogue is **not a feature roadmap**.

It is a deliberately expansive test space.

We should not initially ask:

> "Can our DSL represent this?"

Instead, for every case we should ask:

> "What does this case require an author to express?"

Then compare all cases to discover the smallest useful set of general abstractions.

Only after that analysis should we decide:

- what belongs in the core language,
- what belongs in domain libraries,
- what belongs in the physics/math/chemistry engines,
- what belongs in the renderer,
- what belongs in representation adapters,
- what belongs in the interaction system,
- and what genuinely cannot or should not be generalized.
