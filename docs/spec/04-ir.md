# 04 Semantic IR

- **Version:** v0 (draft), 2026-09-30
- **Part:** the serializable form of the core semantics (R-47, D-019, D-036, D-037). It carries what `01` to `03` assign to each construct; it adds no meaning.
- **Scope:** the model, presentation and run IR for the first slice. The reference implementation is the `prismal-ir` crate (`crates/prismal-ir`), whose types are normative for field names in v0.

---

## 1. Principles

- **Restates:** R-45, R-47, R-66.
- **Decisions:** D-019, D-028, D-036, D-037, D-039.
- **Prior art:** follows compiler intermediate representations that are separate from syntax trees (Rust's HIR and MIR, the Modelica flat model); follows FMI's `modelDescription.xml` in describing a model's variables, causality and variability in a tool-neutral file; follows JSON Schema practice for versioned documents.

- **IR-1.1** The IR records what the author **meant** (R-47): resolved identities, roles, types, flow kinds, trigger directions. It does not record layout, keyword spelling or the choice between equivalent surface forms. A syntax tree is a separate, tool-internal structure.
- **IR-1.2** The IR is **complete**: every construct of `01` to `03` has a form here, and a model can be built, checked, run and printed from the IR alone, without source text (D-019).
- **IR-1.3** The serialization is **JSON** (D-037), UTF-8, with a format tag and version. Numbers are binary64; a writer MUST print them so that reading gives back the same binary64 value (shortest round-trip form).
- **IR-1.4** Every declared element has an **identity** (`id`): an opaque string, unique within the document, stable across edits that do not remove the element (MK-7.6, D-036). References between elements use identities, never names.
- **IR-1.5** Every declared element MAY carry **notes**: the author's documentation comments (D-036). Notes have no meaning; tools preserve them.
- **IR-1.6** Elements MAY carry a **source span** (file, line, column) for diagnostics. Spans have no meaning and are dropped when the IR is edited visually.
- **IR-1.7** Order: the order of elements in a list is their **identity order** where the kernel needs one (MK-13.6, MK-14.10). Tools MUST preserve it; a new element is appended.

## 3. Dimensions, units and types

- **Dimension:** an object of rational exponents over the seven SI base dimensions, omitting zeros: `{"L": 1, "T": -2}`; a rational exponent is written `[1, 2]`. The empty object is dimensionless (MK-3.1).
- **Unit** (in literals and display metadata): `{"text": "m/s^2", "scale": 1.0, "offset": 0.0, "dim": {"L": 1, "T": -2}}`. `text` is what the author wrote and is used only for display (MK-3.7).
- **Type:**

| Kind | JSON |
|---|---|
| Boolean, Integer | `{"kind": "boolean"}`, `{"kind": "integer"}` |
| Quantity (Real is dimensionless) | `{"kind": "quantity", "dim": {...}}` |
| Instant | `{"kind": "instant", "dim": {...}}` |
| Point, Vector | `{"kind": "point", "space": id}`, `{"kind": "vector", "space": id, "dim": {...}}` |
| Tuple | `{"kind": "tuple", "items": [type, ...]}` |
| Enumeration | `{"kind": "enum", "cases": ["flying", "grounded"]}` |
| Function | `{"kind": "function", "params": [type, ...], "result": type}` |

## 4. Spaces

## 5. Models

```json
{
  "id": "m1", "name": "Projectile", "default_space": "s1", "notes": [],
  "bindings": [ ... ], "processes": [ ... ], "flows": [ ... ],
  "events": [ ... ], "equations": [ ... ], "constraints": [ ... ]
}
```

### 5.1 Bindings

`{"id", "name", "role", "type", "init", "def", "intervenable", "private", "display": {"symbol", "unit"}, "notes"}`

- `role`: `constant`, `parameter`, `input`, `discrete`, `continuous`, `derived` (MK-6.2).
- `init`: the initial definition (stored roles except `input`). `def`: the defining expression (`derived`); for a derived function value (MK-10.7) it is a `lambda`.
- `intervenable`: explicit for state; parameters are intervenable unless it is `false` (MK-6.10).

### 5.2 Processes and flows

- Process: `{"id", "name", "kind": "continuous", "notes"}` (MK-14.1).
- Flow: `{"id", "target": binding-id, "kind": "define" | "contribute", "expr", "process": id | null}` (MK-14.7).

### 5.3 Events

`{"id", "name", "trigger", "enable", "handler": [op, ...], "zeno", "payload": type | null, "notes"}`

- Trigger: `{"kind": "falling" | "rising" | "crossing", "guard": expr}`, `{"kind": "at", "time": expr}`, `{"kind": "every", "period": expr, "from": expr}`, `{"kind": "on", "event": id}`, `{"kind": "start"}`, `{"kind": "input", "binding": id}`, `{"kind": "request"}`. The form `{"kind": "level", "cond": expr}` exists only so that invalid IR (RP-01.D1) can be represented and rejected (MK-E13).
- Zeno: `null`, `{"policy": "stop"}` or `{"policy": "settle", "ops": [...]}`, with optional `eps`, `n`, `window` (MK-15.13).
- Operation: `{"op": "set", "target": {"binding": id, "component": null | index}, "value": expr}`, `{"op": "contribute", ...}`, `{"op": "emit", "event": id, "payload": expr | null}`. Structural operations (`create`, `destroy`, `connect`, `disconnect`) are reserved with collections and relations.

### 5.4 Equations and constraints

- Equation: `{"id", "name", "lhs", "rhs", "role": "display" | "check", "tol": expr | null}` (MK-11).
- Constraint: `{"id", "name", "cond", "tol": expr | null, "policy": "reject" | "report" | "stop", "attached_to": binding-id | null}` (MK-12). `attached_to` records that the author wrote the constraint on a parameter (`where`, `in`), so it prints back there (D-028); it has no meaning.

## 6. Expressions

Every expression is an object with one tag field. Expressions keep their symbolic structure (MK-10.6).

| Form | JSON |
|---|---|
| number literal | `{"num": 9.81, "unit": unit | null}` |
| Boolean literal | `{"bool": true}` |
| enumeration case | `{"case": "flying"}` |
| binding read | `{"ref": id}` |
| lambda parameter | `{"param": index}` |
| built-in | `{"builtin": "t" | "t0" | "elapsed"}` |
| named constant | `{"const": "pi"}` (D-039) |
| origin | `{"origin": space-id}` |
| derivative | `{"der": binding-id}` (MK-11.5) |
| unary | `{"neg": e}`, `{"not": e}`, `{"norm": e}` |
| binary | `{"bin": "add" | "sub" | "mul" | "div" | "pow" | "and" | "or" | "eq" | "ne" | "lt" | "le" | "gt" | "ge", "l": e, "r": e}` |
| function call | `{"call": "sin" | "cos" | "tan" | "sqrt" | "exp" | "log" | "abs" | "min" | "max" | "atan2", "args": [e, ...]}` |
| application | `{"apply": e, "args": [e, ...]}` |
| conditional | `{"if": e, "then": e, "else": e}` |
| tuple | `{"tuple": [e, ...]}` |
| component | `{"comp": e, "axis": index}` |
| lambda | `{"lambda": {"params": [type, ...], "body": e, "names": [text, ...]}}`; `names` are the parameter names as written, for display only (`f(x) = a x^2`, D-034) |
| status handling | `{"otherwise": e, "default": e}` |

- Chained comparisons lower to `and` of pairwise comparisons.
- A tuple's vector type (D-032) is decided by the checker and is not stored; the IR stays what the author wrote.
- Literal magnitudes are stored as written, with their unit; the checker converts to coherent SI (MK-3.7). A minus sign written directly on a number literal belongs to the literal: `-5` is `{"num": -5}`.
- The IR holds no infinities (JSON cannot represent them): an unbounded interval end lowers to a one-sided comparison.

## 7. Presentations and runs

The reference implementation is `crates/prismal-ir/src/present.rs`. Expressions are model expressions (section 6) read in the scope of the presentation's model; inside an inverse, `{"param": 0}` is the gesture's value. Identities follow declaration paths (D-036): `Pres.observe.name`, `Pres.view.name`, `Pres.scene.name`, `Pres.beat.name`; a representation is `container.name` when named, otherwise `container.kind.n`, the n-th of its kind in its view or beat; a run is its name, and its expectations `Run.expect.n`.

### 7.1 Presentation

`{"id", "name", "model": id, "observations": [...], "views": [...], "permissions": [...], "timeline": timeline | null, "notes"}` (PK-2.1).

- Observation: `{"id", "name", "source", "schedule"}` (PK-3.1).
  - Source: `{"kind": "expr", "expr"}`, `{"kind": "event_log", "event": id | null, "zeno_only": bool}`, `{"kind": "diagnostics", "element": id | null}`, `{"kind": "intervention_log"}`.
  - Schedule: `{"kind": "live"}`, `{"kind": "every", "period"}`, `{"kind": "at", "time"}`, `{"kind": "on", "event": id, "microstep": n | null}`, `{"kind": "over", "from", "to": expr | null, "lo_closed", "hi_closed"}` (a null `to` is the end of the run), `{"kind": "run"}` (no schedule written: the whole run).
- View: `{"id", "name", "kind", "representations": [...]}` with kind `{"kind": "spatial", "space": id, "scale": scale, "y_up": bool}`, `{"kind": "plot", "x": [lo, hi], "y": [lo, hi]}` or `{"kind": "panel"}` (PK-7.2, PK-7.3).
- Scale: `{"quantity": expr, "px": n}`: the quantity maps to `n` view pixels (PK-5.5).
- Representation: `{"id", "name": text | null, "kind", "sources": [arg, ...], "props": [{"name", "value": arg}, ...], "inverse": inverse | null, "members": [representation, ...]}` (PK-6.1); `members` is present only for a `group` (PK-6.3b, D-043), whose members are identified within it (`P.view.scene.body.marker.1`). An argument is `{"kind": "expr", "expr"}`, `{"kind": "text", "text"}`, `{"kind": "range", "lo", "hi"}`, `{"kind": "scale", "scale"}`, `{"kind": "word", "word"}`, for a sampled source (PK-6.3a) `{"kind": "sampled", "expr", "every"}`, or, for a model element that is not a value (an event for `button`, an equation for `equation`), `{"kind": "element", "element"}`. The timeline action `hide` is `{"action": "hide", "target", "duration"?}`; `reveal` is `{"action": "reveal", "view"?, "style": "fade" | "draw", "duration"?, "reps"}` and `camera` is `{"action": "camera", "view", "center"?, "zoom"?, "duration"?}` (D-042).
- Inverse: `{"gesture": "drag", "part": text | null, "proposals": [{"target": binding-id, "value": expr}, ...]}` (PK-5.6).
- Permission: `{"role": "learner", "allows": ["timeline_controls", "zoom", "pan"]}` (PK-10.4).

### 7.2 Timeline

`{"scenes": [{"id", "name", "beats": [{"id", "name", "actions": [...]}]}]}` (PK-9.1). Each action is an object tagged by `action`:

| Action | JSON |
|---|---|
| show | `{"action": "show", "view": id | null, "reps": [...]}` (`in V { reps }`, or `show rep` over the presentation) |
| highlight | `{"action": "highlight", "target": representation-id}` |
| narrate | `{"action": "narrate", "text", "duration": expr | null}` |
| run, hold | `{"action": "run", "rate": expr}`, `{"action": "hold"}` |
| seek, reset, branch | `{"action": "seek", "time": expr}`, `{"action": "reset"}`, `{"action": "branch"}` |
| intervene, request | `{"action": "intervene", "ops": [op, ...]}`, `{"action": "request", "event": id}` |
| wait, wait_until | `{"action": "wait", "duration": expr}`, `{"action": "wait_until", "event": id}` |
| explore | `{"action": "explore", "limit": expr | null, "keep": [binding-id, ...], "controls": [rep, ...], "fallback": [action, ...]}` |
| sequence | `{"action": "sequence", "actions": [...]}` |

The shorthand `run rate r until E` is stored as the two actions `run` and `wait_until` (D-028); the formatter prints them back as the shorthand when a beat holds exactly those two.

### 7.3 Runs

A run case (RC section 3, PK section 4): `{"id", "name", "model": id, "presentation": id | null, "params": [{"binding", "value"}, ...], "config": {"solver", "h", "rtol", "atol"}, "end": expr | null, "learner": [step, ...], "expectations": [...]}`.

- Learner step: `{"at": expr, "input": {"kind": "continue"} | {"kind": "set_control", "control": "slider", "binding": id, "value": expr}}`. A learner script is test-harness input fed through the interaction path (reference programs README).
- Expectation: `{"id", "check": ...}` with
  - `"equal"`: `{"subject", "expected", "tolerance"}`, where the expected operand is `{"kind": "value", "expr"}`, `{"kind": "subject", "subject"}` or `{"kind": "list", "items": [{"kind": "event", "event"} | {"kind": "value", "expr"}, ...]}`, and the tolerance `{"kind": "exact"}`, `{"kind": "abs", "tol"}` or `{"kind": "rel", "tol"}`;
  - `"within"`: `{"subject", "lo", "hi", "lo_closed", "hi_closed"}`;
  - `"outcome"`: `{"outcome": "initialization_fails" | "configuration_rejected"}`.
- Subject: `{"kind": "observation", "observation": id, "index": n | null}` (the n-th value of a series, from 1), `{"kind": "on", "expr", "event", "microstep"}` (`(e on E)`), `{"kind": "beat_start", "beat"}`, `{"kind": "beat_end", "beat"}`.
